# Declarative candidate boundary

The local model proposes a JSON rule module. The native MeTTa layer validates
the fixed schema/vocabulary and admits typed facts to &trial. No model text is
imported, consulted or evaluated as code. The exported module.metta is a data
snapshot of those native trial facts, not an arbitrary program entry point.

The interpreter accepts conditions over named voice defects and returns one
of two rendering plans: preserve the candidate, or use existing approved
clause variants. Neither plan is a certificate or an external effect. G22
must execute independently owned tests before promotion can be considered.
The seed parent preserves input; the model authors the conditional policy.

The model cannot choose writable AtomSpaces, host paths, predicates, tests,
success criteria or external effects. Its permitted output is trial guidance.
The native manifest supplies source pressure, lineage, fixed schemas, tests,
rollback target and quarantine standing; hashes bind the actual model request,
raw response, candidate data and parent. Assertions of success by a candidate
have no authority.

Generation consumes the G20 opportunity's finite call allowance. Requests are
recorded before transport, so failed calls still consume allowance. An exhausted
allowance blocks another call before request creation. Provider workers have a
fixed deadline and are reaped on timeout; existing services are not stopped.

This is the expressly bounded first mutable surface in C-092. It does not claim
general reasoning from a rule table, unrestricted generated MeTTa execution,
or successful self-improvement merely because a candidate was generated.
