# AMA-1.2 R3 — Swift high-fidelity build procedure

**Status:** controlling implementation procedure for frozen R3 scope

**Authority:** derived from the frozen R3 plan, Constitution, Soul specification,
Build Fidelity Protocol, Work Protocol, and the five ratified mathematical
authorities. This procedure changes none of them.

## Purpose

Complete the finite PoC inheritance of M24 through M26.3 through one supported,
continuously cycling Miter organism without turning 114 exported meanings into 114
independent gates. Every movement must either add a dependency consumed by the next
movement, produce discriminating evidence that changes the implementation route, or
expose an honest formalization question for 26.6/26.9.

## Work unit: an upstream-closed causal seam

The unit of implementation is the smallest useful cluster of interdependent
authority meanings that can be joined to the existing assistant path without a
parallel service. A cluster is eligible only when:

1. every included atlas row names its exact source meaning and successor consumer;
2. all prerequisites needed for its claimed runtime difference are already present
   or included in the same cluster;
3. the cluster can be severed materially without changing irrelevant presentation;
4. restoration can recover the dependent capacity; and
5. the result advances the same assistant that Berton and Haley will evaluate.

## One-pass implementation cycle

For each causal seam:

1. **Select from the atlas.** Choose an upstream-closed set of rows whose shared
   implementation removes the most downstream gaps. Do not select work by ease or
   by an old gate number.
2. **Bind the constitutive trace.** Before editing cognition, record source meaning,
   native representation, runtime consumer, positive difference, material
   severance, neutral perturbation, restoration, and the next seam that will consume
   it.
3. **Implement once in the organism.** Add generic PeTTa/MeTTa relations and
   operations to the versioned constitutive path. Prolog may provide only
   deterministic carrier, persistence, integrity, process, reconciliation, and
   effect mechanics. No fixture, prompt, model, host-language branch, or expected
   label may supply the semantic result.
4. **Join before claiming completion.** Exercise the new organization through the
   versioned assistant reactor, then through the supported persistent service.
   Native harness evidence may advance a row, but it cannot confer
   `PROVEN-RUNTIME`.
5. **Run one causal matrix.** Require positive, independently severed, neutral,
   restored, malformed/unknown, duplicate, and restart arms as applicable. Check the
   exact dependent difference for each atlas row; do not accept an aggregate score.
6. **Run regressions once.** Execute the fidelity suite and only the old-gate subsets
   whose promoted mechanics the seam can affect. A failure changes the route; a
   byte-identical repeat with no new distinction is stopped.
7. **Record an honest boundary.** Save raw stdout/stderr, process result, hashes,
   environment pin, causal verdict, source-to-consumer trace, and explicit
   non-claims. Failed attempts are retained when they explain a repair or falsify an
   assumption.
8. **Promote atomically.** Update individual atlas rows only to the standing their
   evidence earns. Commit exact R3 paths; never broadly stage and never absorb the
   protected G22/G28 work.
9. **Continue from the dependency frontier.** Select the next seam by which remaining
   cluster unlocks the most later rows while reusing the just-promoted runtime path.
   Refreeze only when authority, source meaning, external scope, interface contract,
   final acceptance, or phase dependency materially changes.

## Economy and stop laws

- A component is not complete because it exists, parses, or passes an isolated
  harness.
- A row is not complete because a neighboring row passed.
- A test is not repeated unless code, input, environment, hypothesis, or expected
  discrimination changed.
- A new wrapper, duplicate runtime, scenario branch, scalar score, or post-hoc Soul
  checker is rejected unless the frozen controls explicitly require it.
- Resource failure is classified before granting more resources. Syntax omission,
  combinatorial search, carrier inflation, persistence cost, and legitimate native
  reasoning are different failures.
- Live Mattermost remains held until R3-C1 through R3-C3, exact identity, both-human
  disclosure consent, integrity, recovery, and grant preflights pass.

## Checkpoint closure

Checkpoint closure is a single review of the integrated organism, not a sum of green
micro-tests. R3-C2 closes only when every operational atlas row is
`PROVEN-RUNTIME`, every boundary row is `REPRESENTED-BOUNDARY`, and the supported
persistent service carries the complete causal organization. R3-C3 then uses that
same organism as the provisional 26.6/26.9 laboratory. R3-C4 activates that same
organism; it may not substitute a new chat wrapper.
