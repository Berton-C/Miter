# G31 P9 R1 — bounded live Mattermost canary

This is the activation and live-evidence phase authorized by Berton. It is limited to two new allowlisted canary contacts, at most two natively VoiceRNA-certified replies, one denied-control contact that cannot enter cognition or produce a reply, one real process restart with no replay, and terminal panic. The capability expires no later than thirty minutes after activation and may be revoked sooner.

The first live inbound strategy is bounded REST polling using Mattermost's `since` lower bound, selected from the Miter-authored REST/WebSocket interface. The lower bound begins at activation, so the bridge need not establish its baseline by reading channel history. Each allowlisted item must pass the exact candidate's identity mapping before its known canary text enters the native current-contact representation. The denied-channel item must be rejected by the candidate from stable metadata before its content is inspected.

For each authorized canary, PeTTa/MeTTa reconstructs the exact P8 approval standing and creates the source/effect-bound `CertifiedUtterance`. Prolog may then construct the candidate's `SurfaceEffect`, write and fsync a pending effect record, commit the exact loopback POST with its stable `pending_post_id`, and store the receipt or an explicit unknown outcome. No raw or held native product can reach POST.

After the first response, the process exits. A new process must read back the cursor and confirmed effect, prove the old candidate effect is duplicate-suppressed without issuing another POST, and then await the second canary. After the second response and denied-control observation, panic closes network/effect reach. Expiry and revocation use the same fail-closed state transition.

Offline source, authority, mode, route, candidate and native-certificate preflight must pass before activation. JavaScript remains builder-side verification only. Every actual credential lookup and HTTP operation belongs to the Prolog membrane; the token is never returned or written. Public evidence contains hashes, timestamps, counts and typed standings, never stable IDs, the human username, token, or raw API responses.
