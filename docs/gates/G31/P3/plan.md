# G31 P3 — form and test the reconciliation-capable candidate

P2 found a usable Mattermost mechanism and an exact incompatibility in the current candidate. P3 gives that source-grounded discrepancy to Miter's native candidate-construction path, permits one bounded OpenRouter semantic contribution, and quarantines the returned full Prolog candidate. The model may render a repair; it cannot declare the repair sufficient.

The candidate must map its stable effect idempotency key into the request body's `pending_post_id` while preserving every prior authorization, identity, edit, cursor, panic, and local duplicate contract. Independent tests reproduce Mattermost 11.7.7's qualified envelope: same principal and same key within 30 seconds returns one created post; an in-flight duplicate is typed; expiry, restart/eviction, changed principal, or missing journal never becomes an exactly-once claim. No local Mattermost endpoint or credential is used.

Passing P3 yields a quarantined, source-compatible candidate eligible for separately planned transport integration. It does not promote or activate the candidate and does not authorize a live canary.
