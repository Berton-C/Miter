# G31 P1 — separate source identity, bot authority, and live readiness

P0 found the candidate container without touching Mattermost, but its grant schema could call a synthetic tuple complete without naming the authorized inbound human/source IDs separately from the credentialed outbound bot. That is an authority error, not a cosmetic field omission.

P1 revises only the native grant ontology and offline causal controls. A live-ready grant must now bind distinct inbound sources and outbound bot, bind the external credential reference to that bot, and include VoiceRNA/certified-movement, qualified transport, and uncertain-effect reconciliation standing in addition to the prior scope, persistence, access, panic, rollback and revocation fields.

P1 repeats no discovery and exposes no credential or network primitive. Passing P1 means the authority request is correctly represented; it does not mean Berton has granted it or that G31 has run.
