# G33 R5 semantic fidelity audit

The implementation consumes the product that R3 identified but did not use:
`RDisposition` returns an actual `repair-request` carrying the first
`voice-audit`. That audit is recomputed from the controlled first candidate and
the current source-grounded intention. No fixture supplies a defect list.

`VConstruct` receives the hash-authenticated, accepted G22 expressive module as
declarative grammar. It derives fragments from the current intention, explores
bounded compositions, and compares them with the current joint relations. R5
does not map an alteration type to an action and does not select a list head or
maximum score. Certification is possible only when the source comparison leaves
exactly one supported expression.

The selected expression is passed back through `RAudit`. The certificate binds
the scope and cut, complete native intention and proofs, original candidate,
failed audit and repair request, accepted capability lineage and module,
construction record, selected expression, fresh faithful audit, and explicit
absence of emission authority. `RRVerify` recomputes that entire record from the
current participants before comparing it with a supplied certificate.

Prolog verifies fixed accepted hashes, projects JSON into native data, rejects
non-canonical or symlinked capability paths, checks the accepted-development
receipt binds the same module, bounds search fuel, and joins words. It does not
read a defect, choose a fragment, interpret meaning, compare alternatives, or
mint a certificate. JavaScript controls only isolation, source cuts, capture,
and structural verification.

The canonical source frame leaves one supported result only because its
human-confirmed co-expression relation binds all three retained participations.
Removing that relation leaves multiple alternatives and no certificate.
Reordering source records or declarative constructions preserves semantic
content. Removing one material participation changes the derivation rather than
allowing compensation. Removing the fresh audit, changing the scope/cut,
changing accepted bytes, using a symlink alias, presenting the first candidate
as a certificate, or presenting a stale certificate all remain uncertified.

This is a finite, disclosed integration experiment. It does not establish
general language understanding, that every unique construction is beneficial,
public `RRun`/`RWait` repair integration, effect eligibility, or G33 completion.
