## Typed mechanical operations

Provide create_candidate_worktree, write_candidate_file, read_candidate_file, list_candidate_tree, run_declared_test, get_diff/get_test_artifact and discard_candidate with stable request/idempotency IDs. Build/fixture/promotion operations not yet implemented return explicit unsupported standing, never arbitrary command fallback. The native wrapper carries typed results; Prolog performs no Soul decision. Every attempted operation has an additive, hash-linked result. Exact replay does not repeat effects; conflicting reuse is rejected. Candidate writes are limited to declared extension and candidate-test subtrees. Main/control/judge paths and path/symlink traversal are rejected.

Docker execution has fixed argv (not a model-supplied shell command), no network, a read-only root filesystem, dropped capabilities, no-new-privileges, unprivileged user, scoped writable workspace, bounded temporary storage and CPU/memory/PID/time/output limits. The candidate cannot supply flags, mounts, environment secrets or network changes. Time/output exhaustion produces typed incomplete evidence and terminates only the test-owned container.

## Frozen tests

Positive: create a branch/worktree from the pinned isolated seed, write/read a small harmless artifact, execute independent declared shell contract tests, retrieve output/diff and discard recoverably. Verify immutable seed/main and control hashes, candidate branch lineage, request replay count and distinct conflict response.

Adversarial: missing IDs/grant, path traversal, absolute path, symlink escape, canonical/test/metadata writes, arbitrary command or runner parameters, secret/socket/host process access and undeclared network. Use only synthetic canaries and inert paths; never mount a real credential or user's home to prove protection. Fixed sandbox inspection verifies namespaces, mounts and declared resource flags as well as observed attack outcomes. Merely getting a failing command is not enough.

Severed: a separately constructed deliberately permissive profile exposes a synthetic outside-workspace canary. The independent containment checker must detect the extra mount/profile defect, and an isolated canary read must demonstrate the missing boundary. This profile is never available through the production broker and is never promoted. Restore the fixed profile and the same probe loses access. Neutral request/candidate labels preserve useful work and containment.

## Limits and next gate

These are finite sandbox checks, not proof against kernel/engine exploits or all possible programs. No network fixtures or credentials are needed. Candidate security controls are mechanical authority boundaries, not a replacement for Soul reasoning. Keep historical failed trials and exact outputs; no running user service is stopped.

G28 must then originate a small nonnetworked adapter through Miter's native opportunity/generation/trial/revision path and obtain independent review plus a promotion proposal. The builder may supply contract tests and generic mechanics, not counterfeit Miter authorship. Explicit approval remains necessary for promotion as required by ACCEPTANCE; live reach remains separately gated.
