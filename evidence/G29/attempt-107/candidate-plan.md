The SWI-Prolog bridge is a non-cognitive transport/identity membrane because it only maps authenticated Mattermost surface events and effects into stable identity tuples and typed surface contracts; it does not interpret intent, generate meaning, or hold memory beyond core-derived scope. Authorization precedes cognition because every inbound event is first checked against the authenticated server/team/channel/user identity and permission grant before any downstream processing or effect is allowed. Stable identities bind server, team, channel, user, post, root, timestamp, and cursor so that the same logical entity remains consistent across reconnects and edits. Duplicate and effect idempotency are enforced by stable effect IDs and idempotency keys so that retries and duplicate deliveries do not create new side effects. Edits are represented as versioned updates to the same stable identity rather than new entities, preserving history and enabling rollback. Durable cursor and reconnect allow the bridge to resume from the last acknowledged cursor and suppress already-processed events. Typed failure witnesses convert transport or API errors into structured surface failure events instead of untyped crashes. Fixed local panic stops new outbound effects locally while preserving state for recovery. Credential isolation keeps secrets in the bridge environment and never exposes them to the surface or downstream consumers. Core-derived memory scope limits retained state to what is derived from the authenticated surface and channel context. Versioned rollback allows safe reversion of projections without losing history. G30 tests verify authorization, duplicate suppression, edit handling, unauthenticated rejection, send failure, reconnect, cursor resume, and panic behavior, ensuring the bridge remains a safe, non-cognitive transport and identity membrane.
